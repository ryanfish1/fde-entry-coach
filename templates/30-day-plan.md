## Week 1 — Discover the real problem

### Deliverables

- [ ] One-sentence problem brief
- [ ] PSF score with evidence
- [ ] Baseline measurement
- [ ] Minimum Five Maps
- [ ] One real user committed to testing

### Acceptance criteria

The problem describes one real workflow owned by one real user. At least one baseline metric exists. The project is narrow enough to test within 30 days.

## Week 2 — Build the MVD

### Deliverables

- [ ] End-to-end workflow works on real or realistically messy user data
- [ ] 3–10 representative eval cases
- [ ] Human-review boundary defined
- [ ] Basic deployment / access path available to the target user
- [ ] Deployment notes recorded

### Acceptance criteria

The user can complete the target workflow without the builder manually simulating the core output.

## Week 3 — Drive real usage

### Deliverables

- [ ] At least 3 real-use sessions or a comparable repeat-use sample
- [ ] Friction log
- [ ] Top three tomorrow-use blockers fixed or explicitly deferred
- [ ] Quality / usage / value metrics updated
- [ ] User feedback captured verbatim where appropriate

### Acceptance criteria

There is evidence of actual use, not only a demo. The project has at least one before/after comparison.

## Week 4 — Productize the learning

### Deliverables

- [ ] One reusable component, checklist, connector, eval, or workflow pattern
- [ ] One-page FDE Case Study
- [ ] GitHub README
- [ ] 3-minute interview story
- [ ] Expansion / stop decision using the graduation rule

### Acceptance criteria

A third party can understand the problem, deployment, result, limitations, and what can be reused next time.
